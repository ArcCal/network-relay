# 2026-10-01 implementation and specification review

This round checked and fixed the existing features, keeping TCP/UDP relaying over HTTP/1.1, HTTP/2 and HTTP/3, authentication, the website, configuration reload and profile generation; no new user features were added. The profile options implemented earlier are also kept.

The review covered request classification, target resolution and access policy, authentication and revocation, flow control and half-close, capsules/datagrams, resource release, TLS/certificate renewal, configuration validation, the website, logging, the self-check and profiles. Conclusion: the problems confirmed in this round are fixed and covered by regression tests; this is not a certification of conformance with every RFC clause or every Apple OS version.

## Specification sources

The specifications and schema source files in the official repositories were actually read. Web access was restricted by the network policy of the environment used, so web pages that could not be opened were not counted as read, and the RFC Editor's online errata were not checked independently.

- [Apple Relay payload schema](https://github.com/apple/device-management/blob/09f249a06e7e3289930bf6d05f38fb562f748ebf/mdm/profiles/com.apple.relay.managed.yaml): keys, types, supported versions and deprecation status. The legacy payload is supported since iOS 17/macOS 14 and marked deprecated from 27, not removed; this round did not switch to DDM.
- [RFC 9298 published source](https://github.com/ietf-wg-masque/draft-ietf-masque-connect-udp/blob/815f5f3a9ff3765c6efd7fd6449c8062cc17052f/draft-ietf-masque-connect-udp.md): §2 templates, §3 CONNECT-UDP, §4 contexts, §5 UDP length and packet loss.
- [RFC 9297 published source](https://github.com/ietf-wg-masque/draft-ietf-masque-h3-datagram/blob/d6843cfb9866312561af6d3c000ce1a75b40d39f/draft-ietf-masque-h3-datagram.md): datagram negotiation and association with requests, skipping capsules, truncation and error handling.
- [RFC 9113 published source](https://github.com/httpwg/http2-spec/blob/670dbedffb04d2470cc1ebf2ceccdabc6677a823/draft-ietf-httpbis-http2bis.xml): §8.5 DATA on CONNECT, half-close and TCP RST propagation.
- [RFC 9114 published source](https://github.com/quicwg/base-drafts/blob/0921ecf145ab25f3936531462bdde145ce07ebcf/rfc9114.md): §4.4 frame restrictions and cancellation on CONNECT, §7.2 frame validation.
- [Envoy CONNECT/Upgrade documentation](https://github.com/envoyproxy/envoy/blob/a469f264187c8d70f69fa69ad0fceccd846c6ea7/docs/root/intro/arch_overview/http/upgrades.rst) and [Cloudflare quiche HTTP/3 implementation](https://github.com/cloudflare/quiche/blob/cdf610571c76f0a41927466b6e27c6ec12e3fc82/quiche/src/h3/mod.rs): used as implementation references, especially for telling CONNECT and CONNECT-UDP apart and for datagram negotiation at both the HTTP and QUIC layers; not taken as proof of Apple compatibility.

## Fixes and evidence

| Problem | Fix and regression check |
|---|---|
| After an HTTP/2 request half-closed, a client reset on an idle target did not release the tunnel promptly | Watch for RST on the send side separately; a regression test confirms the slot is released, and normal half-close and multi-stream transfers still pass |
| HTTP/3 idle STOP_SENDING, connection loss after half-close, and revocation while the response is blocked by flow control | Pass through Quinn's cancellation notifications; sending the response also watches for revocation; target RST and slot release are verified |
| CONNECT accepted illegal trailing HEADERS | HTTP/2 returns PROTOCOL_ERROR; HTTP/3 closes the connection immediately with H3_FRAME_UNEXPECTED without waiting for FIN |
| Empty or truncated HTTP/3 DATA taken as the end of the stream | Local patch to the upstream frame handling; empty DATA and truncated DATA with no payload are sent on a real QUIC connection, checking the following data and H3_FRAME_ERROR |
| A closed UDP write side treated as packet loss; the background write task could block for a long time | Tell a full queue apart from a closed write side; a normal close drains within a bound, an abnormal close resets promptly; blocked writes, normal draining and close notifications are covered |
| The UDP size limit wrongly applied to unknown contexts | Discard unknown contexts as a stream; reject context 0 payloads over 65527 bytes as early as possible; covers a 70000-byte unknown context, empty packets, non-minimal context encodings and truncation |
| Continuous packet reception or waiting on UDP writes affected cancellation | Bound each batch receive; move cancellation and idle timeout outside the whole forwarding operation; tell temporary ICMP/PMTU errors apart from a failed socket |
| Custom template separators could appear in the host name | Full matching with a bounded work budget, handling overlapping separators, consistency of repeated variables and omitted non-target variables |
| Website file symlinks could expose files outside the root or hidden files; boundary problems in reads and custom headers | Verify link targets, bound the number of bytes actually read, reject framing fields, keep only one value for legitimate overrides |
| Some configuration or profile input failed at a later stage or even panicked | Validate the semaphore limit, complete Argon2 parameters, XML characters, trailing dots on domains and the leading slash of templates; file descriptor estimates use saturating arithmetic |
| Some self-check DNS/HTTP/3 steps had no timeout; incomplete address fallback after TLS failure | Add the timeouts and the address attempts after TLS failure; validate DNS label and total length; verified with a scenario where the handshake fails on the first address and succeeds on the second |

The local changes to the HTTP/3 dependencies are recorded in [h3 PATCH.md](../vendor/h3/PATCH.md) and [h3-quinn PATCH.md](../vendor/h3-quinn/PATCH.md), keeping the source, pinned versions and original licenses.

## Verification

Linux x86_64, Rust 1.98.1. The automated tests use real TLS, QUIC, TCP and UDP connections, and check the specific error codes and target-side behavior.

- `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`.
- `cargo test --locked`, `cargo test --locked --release`: 94 unit tests, 30 integration tests.
- The 30 integration tests were run concurrently 10 times in a row, then serially once, 330 runs in all, every one passing. The repeated runs also found a race in the original DNS test between two equal deadlines; it now reads the server's error response directly, so a client timing out first cannot cause a false failure. The final verification did not set any environment variable to shorten the system DNS retry time.
- Standalone curl 8.14.1 verified the HTTP/1.1 and HTTP/2 website and CONNECT; the full CLI self-check passed against standalone Python TCP/UDP targets.
- Python's standard-library `plistlib` independently parsed the generated Apple configuration, verifying structure, types, template URL, Unicode and XML escaping.

## Verification conditions not yet covered

There were no real iPhone/iPad/Mac devices, no real MDM/user enrollment, no packet capture on a low-MTU link and no long-running wide-area load environment; no arm64 cross-compiler or QEMU was installed locally either. The existing arm64 CI configuration is kept, but this round does not claim it has run and passed. Optional extensions that the standards allow were not added because of this review; unimplemented optional capabilities were not listed as defects in the base protocol.
