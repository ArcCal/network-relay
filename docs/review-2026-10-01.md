# 2026-10-01 实现与规范复查

本轮在已有功能上检查并修错，保留 HTTP/1.1、HTTP/2、HTTP/3 的 TCP/UDP 中继、认证、网站、配置热更新和描述文件生成；没有增加新的用户功能。此前已实现的描述文件选项也予以保留。

检查覆盖请求分类、目标解析与访问策略、认证及撤销、流控和半关闭、Capsule/Datagram、资源释放、TLS/证书更新、配置校验、网站、日志、自检及描述文件。结论是：本轮确认的问题已修复并有回归覆盖；这不是对全部 RFC 条款或所有 Apple 系统版本的符合性认证。

## 规范依据

实际读取官方仓库中的规范及 schema 源文件。网页访问受当前网络策略限制，因此没有把无法打开的网页当作已读资料，也未独立核对 RFC Editor 在线勘误。

- [Apple Relay payload schema](https://github.com/apple/device-management/blob/09f249a06e7e3289930bf6d05f38fb562f748ebf/mdm/profiles/com.apple.relay.managed.yaml)：字段、类型、支持版本及弃用状态。传统负载自 iOS 17/macOS 14 支持，27 起标为弃用，并非已移除；本轮没有改为 DDM。
- [RFC 9298 发布版源文件](https://github.com/ietf-wg-masque/draft-ietf-masque-connect-udp/blob/815f5f3a9ff3765c6efd7fd6449c8062cc17052f/draft-ietf-masque-connect-udp.md)：§2 模板、§3 CONNECT-UDP、§4 Context、§5 UDP 长度和丢包。
- [RFC 9297 发布版源文件](https://github.com/ietf-wg-masque/draft-ietf-masque-h3-datagram/blob/d6843cfb9866312561af6d3c000ce1a75b40d39f/draft-ietf-masque-h3-datagram.md)：Datagram 协商与请求关联、Capsule 跳过、截断及错误处理。
- [RFC 9113 发布版源文件](https://github.com/httpwg/http2-spec/blob/670dbedffb04d2470cc1ebf2ceccdabc6677a823/draft-ietf-httpbis-http2bis.xml)：§8.5 CONNECT 的 DATA、半关闭和 TCP RST 传播。
- [RFC 9114 发布版源文件](https://github.com/quicwg/base-drafts/blob/0921ecf145ab25f3936531462bdde145ce07ebcf/rfc9114.md)：§4.4 CONNECT 的帧限制及取消处理，§7.2 帧校验。
- [Envoy CONNECT/Upgrade 官方文档](https://github.com/envoyproxy/envoy/blob/a469f264187c8d70f69fa69ad0fceccd846c6ea7/docs/root/intro/arch_overview/http/upgrades.rst) 和 [Cloudflare quiche HTTP/3 实现](https://github.com/cloudflare/quiche/blob/cdf610571c76f0a41927466b6e27c6ec12e3fc82/quiche/src/h3/mod.rs)：作为实现对照，尤其是 CONNECT 与 CONNECT-UDP 的区分，以及 HTTP/QUIC 两层 Datagram 协商；不作为 Apple 兼容性证明。

## 修复与证据

| 问题 | 修复及回归检查 |
|---|---|
| HTTP/2 请求半关闭后，空闲目标上的客户端复位不能及时释放隧道 | 独立监听发送侧 RST；回归测试确认名额释放，正常半关闭和多流传输仍通过 |
| HTTP/3 空闲 STOP_SENDING、半关闭后的连接丢失、响应流控阻塞时的撤销 | 透传 Quinn 的取消通知；响应发送也监听撤销；验证目标 RST 和名额释放 |
| CONNECT 接受非法尾部 HEADERS | HTTP/2 返回 PROTOCOL_ERROR；HTTP/3 立即关闭连接并返回 H3_FRAME_UNEXPECTED，不等待 FIN |
| HTTP/3 空 DATA/截断 DATA 被误判为结束 | 局部修补上游帧处理；在真实 QUIC 连接上发送空 DATA 和无负载的截断 DATA，检查后续数据和 H3_FRAME_ERROR |
| UDP 写端关闭被当作丢包、后台写任务可能长期阻塞 | 区分队列满和写端关闭；正常关闭有界排空，异常关闭及时复位；覆盖阻塞写、正常排空及关闭通知 |
| 不认识的 Context 被错误套用 UDP 大小上限 | 流式丢弃未知 Context；Context 0 尽早拒绝超过 65527 字节的负载；覆盖 70000 字节未知 Context、空包、非最短 Context 编码和截断 |
| 连续收包或等待 UDP 写入影响取消处理 | 单次批量接收有界；将取消和空闲超时放到整个转发操作之外；区分临时 ICMP/PMTU 错误与套接字失效 |
| 自定义模板的分隔符可能出现在主机名中 | 有限工作预算的完整匹配，处理重叠分隔符、重复变量一致性及省略的非目标变量 |
| 网站文件软链接可暴露根目录外/隐藏文件，读取和自定义头存在边界问题 | 验证链接目标，读取实际字节数有界，拒绝帧控制字段，合法覆盖只保留一个值 |
| 部分配置或描述文件输入在后续阶段失败甚至 panic | 校验 semaphore 上限、Argon2 完整参数、XML 字符、域名末尾点和模板起始斜杠；文件描述符估算使用饱和运算 |
| 自检 DNS/HTTP/3 部分步骤没有超时，TLS 地址回退不完整 | 补全超时及 TLS 失败后的地址尝试；校验 DNS 标签和总长度；用第一个地址握手失败、第二个地址成功的场景验证 |

HTTP/3 依赖的局部变更分别记录在 [h3 PATCH.md](../vendor/h3/PATCH.md) 和 [h3-quinn PATCH.md](../vendor/h3-quinn/PATCH.md)，保留源码、固定版本及原许可证。

## 验证

使用 Linux x86_64、Rust 1.98.1。自动化测试包括真实 TLS、QUIC、TCP、UDP 连接，并检查具体错误码及目标端行为。

- `cargo fmt --check`、`cargo clippy --locked --all-targets -- -D warnings`。
- `cargo test --locked`、`cargo test --locked --release`：94 项单元测试、30 项集成测试。
- 30 项集成测试连续并发运行 10 轮，再串行运行 1 轮，共 330 次全部通过。重复验证还发现了原 DNS 测试的等长截止时间竞态；改为直接读取服务器错误响应，避免客户端先超时造成假失败。最终验证没有设置缩短系统 DNS 重试时间的环境变量。
- 独立 curl 8.14.1 验证 HTTP/1.1、HTTP/2 网站和 CONNECT；完整 CLI 自检对独立 Python TCP/UDP 目标通过。
- Python 标准库 `plistlib` 独立解析生成的 Apple 配置，验证结构、类型、模板 URL、Unicode 及 XML 转义。

## 尚未覆盖的验证条件

没有 iPhone/iPad/Mac 真机、真实 MDM/user enrollment、低 MTU 链路抓包或长时间广域网压力环境；本机也未安装 arm64 交叉编译器/QEMU。现有 arm64 CI 配置保留，但本轮不声称已经运行通过。标准允许的可选扩展不因本次检查而新增；没有将未实现的可选能力误列为基础协议缺陷。
