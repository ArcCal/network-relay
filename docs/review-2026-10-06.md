# Protocol audit and interoperability, 2026-10-06

The early HTTP/3 datagram age bug was reproduced before a local fix. Root Rust,
deployment, vendor, Go and curl checks pass after the fix. H2O transfers pass,
but its unmodified HTTP/3 client reports an error at normal closure; the
diagnosis below separates this from server correctness. Apple system acceptance
is **BLOCKED** pending device details and an authorized, reachable test relay.
No Apple compatibility or production-readiness certification is made.

## Baseline and scope

Actual initial HEAD: `4d0f5eecc4b5acfd14cf255c25ea43c8d70ec1ed`, branch `work`,
clean worktree, matching the requested baseline. No applicable `AGENTS.md` was
found. Linux x86_64, four CPU quota, 32 GiB memory; Rust/Cargo 1.99.0, Go 1.26.8,
Python 3.12.14, OpenSSL 3.5.7. The official Go archive's SHA-256 was checked
against go.dev metadata. curl 8.14.1 uses OpenSSL 3.5.7, nghttp2 1.64.0 and
nghttp3 1.8.0; HTTP2/HTTP3 features and actual proxy options were probed.

Reviewed the request, routing and transfer paths in `server/{over_tcp,over_h3,
mod,pump,h2_stream}.rs`, protocol parsers, `tunnel`, `connect`, `policy`, `limits`,
authentication, TLS/certificate/configuration handling, CLI startup/reload/exit,
profile/check generation and the existing integration/deployment/Go tests.
Also read the manifests, locked dependencies, actual vendor differences and
PATCH.md files, both previous reviews and relevant design/configuration text.
This is a targeted audit, not an exhaustive review of every CLI or dependency.

The call chain is transport parsing and flow control (hyper/h2 or
h3/h3-quinn/quinn, with rustls) → `Kind`/`Incoming` → `authorize` →
`open`/`try_open` admission guards → bounded DNS and destination policy →
`connect::{tcp,udp}` sockets → `pump`/`Tunnel` forwarding → cancellation,
half-close or error → route/socket/connection/tunnel/user/memory guards release.
The application owns authorization, destinations, resource budgets and lifetime;
the libraries own transport frames, TLS, QUIC recovery and stream flow control.

## Findings and retained mechanisms

| Severity/scope | Location and evidence | Outcome |
|---|---|---|
| Medium, bounded stale delivery | `Router::register`: without a subsequent arrival to prune the queue, expired packets were delivered; registering PendingUdp refreshed their timestamps. RFC9297 §2.1 permits dropping or briefly buffering; RFC9298 §5 permits early arrival. Existing one-second TTL is policy, not a normative exact duration. Expanded existing test fails on baseline (`early-before.log`) | Fixed locally: expire by original timestamp, preserve age while pending; no timer or new cache |
| Test reliability | Existing Go client ignored write/close errors, accepted incomplete transfer accounting, did not reliably bound request reads or cleanly run defers | Joined writer result, exact 1 MiB/FIN check, stream and connection deadlines, cleanup, two-flow UDP payload checks |
| Test oracle | Uncontrolled DNS can return NXDOMAIN or time out; a separate preflight warmed/changed resolver behavior. Logs preserve both false expectations | Require exact 502/dns_error or 504/dns_timeout mapping; other status/error combinations fail, no retry |
| Test oracle | curl H2 negative status is not printed by ordinary verbose output (`curl-h2-negative-diagnostic.log`, `curl-h2-trace.log`) | Read proxy trace, retain exact 404/403 and Proxy-Status checks |
| Documentation | Design table described DDM as unsupported despite implemented output | Corrected table; installation still unverified |
| Reference limitation | H2O `tcp_on_write_complete` explicitly closes both directions when client write ends; Go receives a truncated 1 MiB echo | Reference control FAIL; root server passes. No server change to imitate reference limitation |
| Reference client defect | H2O `handle_input_expect_data_frame` ignores the final unknown GREASE frame without forwarding EOS; `on_stream_destroy` reports I/O error even with err=0 and both directions complete | Unmodified H3 close FAIL. Temporary EOF notification in external H2O alone makes close PASS. Root retained RFC9114 §§7.2.8/9 behavior; diagnostic change reverted |

Retained and exercised: classic CONNECT authority versus Extended CONNECT
scheme/path/protocol; H1 GET/Upgrade versus H2/H3 settings; request validation
before dispatch; Capsule structured-field signaling without inventing rejection
rules for absent/unknown parameters; incremental/unknown/context/truncated
capsules; bounded URI matching; Quarter Stream ID and Context ID separation;
Capsules when DATAGRAM is unavailable versus dropping oversized negotiated
DATAGRAMs; stream and connection error scopes; both-direction half-close,

GOAWAY and shutdown. Relevant existing byte-level and integration tests pass.
